Chapter 1
How the System Works
The page at asset.led.go.th/newbidreg/ is the Legal Execution Department’s online search for auction properties (“ค้นหาทรัพย์ประกาศขายทอดตลาด”). It is a classic server-rendered ASP application: the province list is baked into the initial HTML, while districts and sub-districts are fetched lazily by two small XMLHttpRequest helpers as the user drills down.
Three pieces of front-end logic drive the location cascading: loadAmphur(provinceId) fires when the province <select> changes, loadTambon(amphurId) fires on district change, and loadPostcode() copies the selected sub-district’s value into the hidden postcode field. Crucially, the API responses are not JSON — both endpoints return ready-made <option> HTML fragments that the script injects directly into the next dropdown.

Chapter 2
The Two Location APIs
Both endpoints live in the same directory as the search page and answer with an HTML fragment containing one <option> element per administrative unit. The first item is always a placeholder (“---- เลือกอำเภอ ----” / “---- เลือกตำบล ----”) with an empty value, and the last item is typically an empty-name entry with a trailing x000 code that you should discard when parsing.
API 1 — Districts (Amphoe / Khet) GET
# Request — provinceId is the 2-digit province code
GET /newbidreg/get_amphur.asp?provinceId=30 HTTP/1.1
Host: asset.led.go.th

# Response — HTML fragment; option value = 4-digit district code
<option value="">---- เลือกอำเภอ ----</option>
<option value="3001">เมืองนครราชสีมา</option>
<option value="3002">ครบุรี</option>
<option value="3003">เสิงสาง</option>
(34 entries total)
<option value="3000"></option>   <!-- trailing empty entry, discard -->
API 2 — Sub-districts (Tambon / Khwaeng) GET
# Request — amphurId is the 4-digit district code from API 1
GET /newbidreg/get_tambon.asp?amphurId=3001 HTTP/1.1
Host: asset.led.go.th

# Response — option value = POSTAL CODE (5 digits), text = sub-district name
<option value="">---- เลือกตำบล ----</option>
<option value="30000">โคกกรวด</option>
<option value="30000">ในเมือง</option>
<option value="30310">จอหอ</option>
(25 entries total)
Important: sub-districts are identified by name + postal code only. The site never uses a numeric sub-district code — when the user picks a tambon, JavaScript writes the name into the hidden tumbol field and the postal code into the hidden postcode field. A few tambons return an empty postcode, which the form submits as blank.
Quick test with curl
curl -s "https://asset.led.go.th/newbidreg/get_amphur.asp?provinceId=83"
curl -s "https://asset.led.go.th/newbidreg/get_tambon.asp?amphurId=8301"
# 83 = Phuket → 8301 เมืองภูเก็ต, 8302 กะทู้, 8303 ถลาง
Chapter 3
How the Codes Are Numbered
The codes follow the standard Thai government administrative numbering (the same scheme used by the Department of Provincial Administration and reflected in ISO 3166-2:TH), with a few LED-specific additions. Understanding the composition rule lets you derive a district’s parent province, or sanity-check values you scrape.
LevelFormatExampleNotes
Province2 digits30Standard code; Bangkok = 10, unique list of 77
District2+2 = 4 digits30 01First 2 digits = parent province; 01 is usually the capital district (เมือง…)
Sub-districtname + postcodeในเมือง + 30000No numeric code is used by this site
Two quirks are worth knowing before you trust the data blindly. First, the LED list contains extra district codes beyond the official set — mostly Bangkok branch offices with parenthesised names (codes 1052–1071, e.g. คลองสาน(บางลำภูล่าง)) and a duplicate in Nakhon Ratchasima (3033 duplicates 3022 หนองบุญมาก). That is why the full dataset holds 1012 district entries versus the ~878 official amphoe. Second, the on-page province dropdown actually lists Uttaradit twice — code 53 as both อุตรดิต (typo) and อุตรดิตถ์ (correct).

Chapter 7
The Search Endpoint (POST default.asp)
Submitting the form POSTs application/x-www-form-urlencoded data to /newbidreg/default.asp. Location filters travel as plain names with prefixes stripped (the cleanLocationText() helper removes จังหวัด / อำเภอ / เขต / ตำบล / แขวง), plus the postal code from the tambon dropdown’s value. The page also carries a session key pair: a hidden oseckey (observed value 989773 on the sampled page) mirrored by the visible confirmation-code field seckey.

Chapter 9
Implementation Notes
Parsing. Treat the endpoints as HTML fragment APIs: match <option value="…">…</option> with a tolerant regex, strip the BOM character (\uFEFF) that prefixes every district name, drop the placeholder row and any entry whose text is empty. Sort is Thai alphabetical, not by code.
Access. The host currently serves normal browser traffic; requests from outside Thailand may be slow or filtered, so add a realistic User-Agent and retry with backoff. A polite rate of roughly one request per second with two concurrent workers stayed error-free during the harvest that produced this dataset. The endpoints are plain GETs without authentication — only the human confirmation code (seckey) guards the search POST, not the location lookups.
Replicating the dropdown cascade. Load the province table from provinces.csv; on province select, call get_amphur.asp?provinceId={code}; on district select, call get_tambon.asp?amphurId={code} and remember that the option value is the postcode. When submitting a search, send cleaned names — the exact transformation the site performs is stripping the prefixes จังหวัด, อำเภอ, เขต, ตำบล, แขวง from the display text.
Sample verification: province 83 (Phuket) returns 8301 เมืองภูเก็ต / 8302 กะทู้ / 8303 ถลาง; province 10 (Bangkok) returns 64 entries including LED branch codes; amphur 3001 (Mueang Nakhon Ratchasima) returns 25 tambons with postcodes 30000 / 30310.
