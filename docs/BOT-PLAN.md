## สัญญาระหว่างสองบอท

ฐานข้อมูลคือช่องทางเดียวที่สองบอทคุยกัน บอท 1 ไม่รู้จักบอท 2 เลย และบอท 2 ไม่รู้จักบอท 1 เลย

```
บอท 1 เขียน →  parcels (td_verdict = NULL)     ← บอท 2 อ่านตรงนี้
                auction_lots
                auction_rounds
                scrape_runs (stage='scrape')

บอท 2 เขียน →  parcels.td_lat / td_lon / td_verdict / td_eva_price
                parcels.dol_lat / dol_lon / dol_verdict
                coord_queue, dol_quota_ledger
                scrape_runs (stage='enrich_td')
                field_provenance

frontend อ่าน → GET /api/parcels   (อ่าน td_lat ?? dol_lat)
```

**กฎข้อเดียว: บอท 2 ห้ามแตะของที่บอท 1 เขียน** นอกจากคอลัมน์ที่มันเป็นเจ้าของเอง (`td_*`, `dol_*`, `*_verdict`)

## สิ่งที่ไม่ต้องทำ

- **ไม่ต้องเขียนบอทใหม่** — ทั้งสองตัวเขียนเสร็จและใช้งานได้
- **ไม่ต้อง BullMQ / Redis** — `scrapeByProvince.js` เขียนไว้ว่า "without a queue backend yet" แต่ตอนนี้ตารางฐานข้อมูลคือคิวพอ (`coord_queue` มี claim + lease + backoff อยู่แล้ว)
- **ไม่ต้องแตะ DOL นอกเหนือจากโควตา** — 20/วันคือข้อจำกัดของเขา ไม่ใช่ของเรา
- **ไม่ต้องย้อน datum อีก** — วัดจากของจริง 9 จุด 3 จังหวัดแล้ว คลาดเหลือ ~2 ม.
